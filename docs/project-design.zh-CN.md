# PassageLab 项目设计

> C++20 三维刚体通行与运动规划交互式工具。本文定义项目要实现的功能、算法、架构和验收方式；不表示已有代码、完成测试或取得性能结果。

## 1. 项目定义

PassageLab 解决一个明确的问题：**一个具有实际形状和体积的刚体，如何通过包含障碍物和狭窄开口的三维空间？**

用户设置物体、环境、起点和终点，软件计算包含平移与旋转的运动路径，检查路径中的碰撞与间隙，改善路径，并通过交互式三维界面展示结果与计算依据。

典型使用对象包括长条、L 形和不对称的组合物体；典型环境包括狭窄通道、走廊转角和错位开口。物体形状、尺寸与朝向必须真实参与计算，改变这些条件后需要重新规划。

项目由三个核心部分组成：

1. **自研几何模块**：刚体变换、基础几何查询、碰撞检测、空间加速和运动段检查。
2. **运动规划模块**：在 SE(3) 状态空间中实现 RRT-Connect，生成路径并进行受约束的路径简化。
3. **交互式可视化模块**：展示模型、位姿、碰撞、距离、搜索过程与路径比较，并支持用户修改输入和检查结果。

### 1.1 设计目标

| 目标 | 具体表现 |
|---|---|
| 三维几何表达 | 同时处理位置、朝向、物体体积和局部组成部分 |
| 实际运动规划 | 根据输入计算路径，不依赖预先编排的动画 |
| 可解释的查询 | 能说明哪个组成部分与哪个障碍物发生碰撞或距离最近 |
| 可检查的路径 | 对路径段执行明确的验证，并记录验证方法与参数 |
| 可比较的优化 | 分别展示平移长度、累计旋转、间隙与计算成本 |
| 可复现实验 | 保存场景、参数、随机种子、运行环境与原始结果 |
| 可维护的 C++ 工程 | 核心计算独立于图形界面，具有清楚的所有权与测试边界 |

### 1.2 项目边界

首版包含一个可移动刚体、有限数量的静态障碍物、固定起终位姿，以及预设和可调参数的测试场景。

首版不包含：

- CNC、刀具、加工工艺、机床运动学或 G-code。
- 重力、摩擦、受力、搬运者、机械臂动力学或真实搬运安全评估。
- 软体变形、关节运动、多移动物体协同和动态障碍物。
- 任意 CAD 曲面、STEP 导入、任意损坏网格修复。
- 照片级渲染、完整游戏引擎或完整物理引擎。
- 用生成式 AI 替代几何查询和路径验证。
- 全局最优性保证，或根据搜索超时证明无解。

软件回答的是设定模型下的几何通行问题；可行路径不等于真实物体能够按相同方式被搬运。

## 2. 使用流程与功能范围

### 2.1 完整使用流程

1. 打开一个预设场景。
2. 查看物体、障碍物、世界坐标轴和起终位姿。
3. 修改物体尺寸、开口大小或起终位置与方向。
4. 即时检查当前位姿是否碰撞，查看最近距离或碰撞对象。
5. 配置随机种子、搜索预算、扩展步长与运动检查精度。
6. 启动 RRT-Connect，观察受限数量的搜索节点与连线。
7. 获得结果：通过指定检查的路径、预算耗尽、输入无效或主动取消。
8. 对路径播放、暂停、单步和拖动进度；查看关键姿态与最小采样间隙位置。
9. 执行路径简化，比较原始路径与改进路径。
10. 导出场景、路径和运行报告，供再次加载与基准分析。

## 4. 几何模型与数学约定

### 4.1 坐标、单位与位姿

- 使用右手坐标系；世界 Z 轴向上。
- 几何长度统一为米，内部角度为弧度；界面可显示角度值。
- 核心几何计算采用双精度；渲染转换为单精度时保留清楚的边界。
- 位姿由平移向量 `t` 和单位四元数 `q` 构成。
- 文件中四元数固定采用 `[x, y, z, w]` 顺序；库构造函数的参数顺序通过适配函数转换。
- 几何在模型局部坐标中保存；改变位姿不复制或重建全部几何。
- 物体非均匀尺寸变化视为几何编辑，重新生成查询数据，不能混入纯刚体位姿。

局部点到世界点的变换：

```text
x_world = R(q) * x_local + t

T = [ R  t ]
    [ 0  1 ]

T_world_part = T_world_body * T_body_part
```

刚体逆变换为 `R^T` 与 `-R^T t`。两个变换的组合顺序必须通过已知点案例验证，不能凭显示结果猜测。

### 4.2 SE(3) 状态空间

状态记为 `s = (t, q)`，含三维平移和三维旋转自由度。位置相同而方向不同的两个状态，可能具有完全不同的碰撞结果。OMPL 的 SE(3) 表示同样将三维位置与四元数朝向组合使用。[参考：OMPL SE3StateSpace](https://ompl.kavrakilab.org/classompl_1_1base_1_1SE3StateSpace.html)

设两个单位四元数为 `q_a`、`q_b`，旋转距离为：

```text
theta(a,b) = 2 * acos(clamp(abs(dot(q_a,q_b)), 0, 1))
```

使用绝对值处理 `q` 和 `-q` 表示同一旋转的情况。接近零旋转时可采用数值更稳定的等价实现，并通过测试确认。

规划距离使用：

```text
d(a,b) = sqrt(||t_a - t_b||^2 + (rotation_weight * theta(a,b))^2)
```

`rotation_weight` 的单位为米/弧度，可初始取与物体局部包围半径相当的尺度，并作为显式配置保存。该距离用于搜索和扩展，不是实际物体任意点运动长度的严格测量。

### 4.3 位姿插值

```text
t(u) = (1-u) * t_a + u * t_b
q(u) = shortest_arc_slerp(q_a, q_b, u), u in [0,1]
```

插值前对齐四元数符号，处理接近重合与旋转角接近 π 的情况。禁止直接线性插值欧拉角作为主路径表示。

规划扩展、运动检查、路径简化和动画必须采用同一套插值语义。动画速度是展示参数，不代表动力学可执行速度。

### 4.4 几何表示

首版以解析实体为准：

- `Box`：局部中心、三个正的半尺寸。
- `Sphere`：局部中心与正半径。
- `CompoundBody`：若干固定局部位姿的实体组成的集合。
- `Obstacle`：固定世界位姿和实体几何。

长条由一个箱体表达；L 形与不对称物体由多个箱体的并集表达。组合刚体内部允许组成部分相交，不进行内部自碰撞判定；只检查其与外部障碍物的关系。

渲染网格由相同参数生成，避免显示模型与查询模型不一致。若后续使用简化碰撞代理，应同时显示原模型和代理，记录近似方式。

首版不使用“只有三角面相交才算实体碰撞”的规则处理任意闭合网格，因为完全包含也可能构成实体重叠。通用网格的表面/实体语义及内部判定需要单独设计。

### 4.5 场景边界

区分两个概念：

1. **采样边界**：规划器允许采样物体参考点的位置范围。
2. **物理边界**：地板、天花板、墙体或明确要求整个物体留在内部的区域。

物体中心位于采样范围内，不表示整个物体位于物理空间内。物理边界必须作为实体约束检查，防止算法从墙外、顶上或场景背后绕开设计中的通道。

## 5. 自研几何与查询模块

### 5.1 基础查询

| 查询 | 实现要点 | 返回内容 |
|---|---|---|
| 点到线段 | 投影并限制参数区间；处理零长度线段 | 距离、最近点 |
| 点到箱体 | 转入箱体局部空间，再限制坐标 | 内外关系、外部距离、最近点 |
| 球体到球体 | 中心距离与半径和比较 | 碰撞、分离距离；中心重合时的退化标记 |
| 球体到箱体 | 局部最近点；单独处理球心在箱体内 | 碰撞、分离时的距离和最近点 |
| OBB 到 OBB | 分离轴定理，检查面法线和边方向叉积 | 相交/分离/数值不确定 |
| 射线到三角形 | 射线参数、重心坐标与退化处理 | 拾取对象、面、世界坐标 |

对于箱体 SAT，候选轴包括两个箱体各自的三个轴，以及九个两两叉积轴。近乎平行的叉积轴不能直接不加判断地归一化。容差应结合轴长度和几何尺度设置。

碰撞和距离结果使用结构化信息：

```text
QueryResult
  relation: separated | touching | overlapping | indeterminate
  body_part_id
  obstacle_id
  separation_distance: optional<double>
  closest_point_on_body: optional<Vec3>
  closest_point_on_obstacle: optional<Vec3>
  contact_points: optional<list<Vec3>>
  backend
  tolerance_policy_id
```

仅在后端确实提供对应信息时填写最近点、接触点或距离。发生重叠时，不把未知穿透深度写为一个有物理含义的负距离。界面可高亮碰撞对象而不绘制不存在的“精确接触点”。

### 5.2 组合刚体查询

组合刚体与环境的碰撞定义为：存在任意一个组成部分与任意障碍物相交或接触。

分离状态下，整体间隙为所有“组成部分—障碍物”距离的最小值。返回达到该最小值的对象编号和最近点；距离后端失败时返回未知，不能当作安全间隙。

默认接触视为无效。若设置几何余量 `clearance_margin`，则要求间隙严格大于该余量并满足数值判定策略。余量是模型参数，不等于真实世界安全系数。

### 5.3 粗筛与加速

先实现可审查的全遍历基线，再实现静态障碍物 BVH：

1. 计算每个障碍物的世界 AABB。
2. 建立静态 BVH，叶节点保存障碍物编号。
3. 根据移动刚体的当前位姿更新其组成部分 AABB。
4. 碰撞查询利用包围盒排除不可能碰撞的对象对。
5. 距离查询使用包围盒距离作为下界，按当前最小距离进行剪枝。

OBB 的世界 AABB 半尺寸可通过 `abs(R) * half_extents` 计算。AABB 相交只说明需要进一步检查，不能作为精确碰撞结论。

查询正间隙余量时，粗筛必须考虑余量，不能仅跳过所有 AABB 不相交的对象对。距离 BVH 也不能复用只返回重叠对象对的遍历结果。

验收以与全遍历结果一致为前提；性能改善通过实测报告，不预设加速倍数。

### 5.4 数值鲁棒性

- 拒绝 NaN、无穷值、非正尺寸和近零范数四元数。
- 对轻微偏离单位长度的四元数做受控归一化；过大偏差返回输入错误。
- 区分长度容差、角度容差、四元数范数容差和算法停止阈值。
- 长度容差采用绝对项与尺度相关项组合；避免一个常数处理所有场景尺度。
- 接触附近设置明确的保守判定带；不确定状态默认不可用于接受路径。
- 保持碰撞策略、距离阈值和可视化说明一致。
- 保存数值不确定案例，形成回归测试，不静默改变容差使测试通过。

## 6. 状态有效性与运动段验证

### 6.1 状态有效性

一个状态有效，需要同时满足：

1. 数据有限、位姿合法。
2. 参考点满足采样边界，整个刚体满足物理边界约束。
3. 没有与障碍物相交或接触。
4. 若启用几何余量，距离查询成功且间隙超过要求。

状态失败需返回原因，包括越界、碰撞、间隙不足、数据无效或数值不确定。

### 6.2 首版：有明确分辨率的离散检查

对运动段 `a -> b`，不能仅验证 `a` 和 `b`。设局部包围半径为 `r`、平移长度为 `L`、旋转角为 `theta`，采用：

```text
N = max(1,
        ceil(L / translation_step),
        ceil(theta / rotation_step),
        ceil((L + r * theta) / surface_travel_step))
```

检查 `u = 0, 1/N, ..., 1` 处的状态。三个步长必须为正，均写入配置和结果。`L + r * theta` 是这种插值运动下的表面运动尺度上界，用于控制采样密度；**它本身并不能保证采样之间没有碰撞**。

如果所需采样数超过资源限制，应报告检查未完成，不能降低检查密度后仍声称通过。检查过程应支持取消。

返回记录包括检查样本数、实际步长、失败区间或样本位置、失败对象和检查完成状态。首个无效采样点不是连续运动中的精确首次接触时刻。

离散检查存在漏检与计算成本的权衡；OMPL 也明确区分状态检查和运动检查，并说明分辨率过粗可能漏掉中间无效状态。[参考：OMPL State Validity Checking](https://ompl.kavrakilab.org/stateValidation.html)

### 6.3 路径最终复核

搜索得到的路径必须经过独立调用的完整复核流程：

- 起终点与请求一致。
- 所有相邻状态的运动段均完成验证。
- 复核使用不低于搜索阶段的精度。
- 路径属于当前场景版本及几何版本。
- 保存复核方法、参数、样本数和结果。

首版结果应称为“通过指定分辨率的离散检查”，不能标为“连续无碰撞证明”。提高采样密度仍然只是更细的离散检查。

### 6.4 后续：保守自适应检查与连续碰撞

进阶路线包括：

- 根据距离下界和最大位移上界，对运动区间做保守排除或递归细分。
- 对受支持的几何和插值运动集成连续碰撞检测。

保守区间排除可研究以下条件：若在区间起点得到可靠距离下界 `d_lower`，而区间内任意物体点相对该起点的位移上界为 `B`，则 `d_lower > B + clearance_margin` 可用于排除该区间与静态障碍物的接近风险。成立前提包括距离下界可靠、位移界覆盖整个区间、几何模型一致且误差已计入。

无法满足证明条件时继续细分；达到资源或深度限制后返回不确定。不得将普通近似距离直接当作严格下界。

使用连续碰撞后端前，要确认其运动模型与项目 SLERP 插值是否一致，验证支持的形状组合、收敛状态和失败语义。

## 7. 自研 RRT-Connect 规划器

### 7.1 输入与输出

输入包括场景快照、起终位姿、采样边界、距离权重、扩展步长、随机种子、预算和运动验证配置。

输出包括状态、候选/有效路径、搜索统计、验证报告和可选的受限搜索树快照。

结果状态至少包括：

| 状态 | 含义 |
|---|---|
| `Solved` | 找到连接起终点且完成所声明验证的路径 |
| `InvalidStart` | 起点数据无效、越界、碰撞或间隙不足 |
| `InvalidGoal` | 终点不满足相同要求 |
| `BudgetExhausted` | 在指定预算内没有得到通过验证的完整路径 |
| `Cancelled` | 用户或应用请求取消 |
| `ValidationIncomplete` | 候选路径存在，但检查未完成或数值不确定 |
| `Error` | 输入格式、资源或内部错误 |

首版不返回一般性的 `Impossible`。近似到达目标的部分路径不得作为 `Solved` 返回。

### 7.2 采样与最近邻

- 平移在有界区域内均匀采样。
- 旋转使用 SO(3) 的均匀采样方法，不均匀采样欧拉角。
- 可采用四个独立标准正态数归一化为单位四元数的方式，处理极小范数并记录随机数实现。
- 起步使用线性最近邻搜索；保留替换接口。
- 后续加速结构必须支持选定状态距离，不能未经验证地把四元数分量的普通欧氏距离作为旋转距离。
- 目标偏置作为配置项，基础对照可设为零；任何偏置都应报告。

### 7.3 树节点与扩展

```text
TreeNode
  state
  parent_index

Tree
  root_role: start | goal
  nodes
```

节点使用稳定索引引用父节点，避免容器扩容使裸指针失效。两棵树交换活跃角色时保留根的身份。

`Steer(a, b, eta)` 沿统一插值生成向 `b` 前进最多 `eta` 状态距离的目标。距离为零、重复节点和数值上无进展时需直接终止该次扩展。

`Extend(tree, target)` 返回：

- `Trapped`：无法添加经过检查的新状态。
- `Advanced`：添加了新状态，但尚未到达目标。
- `Reached`：连接到了目标状态。

每次扩展都检查完整运动段。`Connect` 连续调用扩展，直到到达、受阻或预算耗尽；内部循环同样检查取消与预算。

### 7.4 算法流程

```text
validate start and goal
if start equals goal:
    return a validated zero-length path

initialize start tree and goal tree

while budget remains and cancellation not requested:
    target = sample_state()
    extension = Extend(active_tree, target)

    if extension != Trapped:
        connection = Connect(other_tree, extension.new_state)
        if connection == Reached:
            candidate = reconstruct_path_using_root_roles()
            verify endpoints, connecting edge and every path segment
            if verification completed and passed:
                return Solved(candidate)

    swap active_tree and other_tree

return the appropriate termination status
```

重建时从起点树回溯到根，再按正确方向拼接终点树路径；避免重复连接节点。若使用“足够接近”的连接条件，仍必须验证两棵树之间剩余的连接段。

该算法采用已有 RRT-Connect 方法，不宣称算法原创或全局最优。对照实现与参数含义可参考 OMPL 的 RRTConnect 文档。[参考：OMPL RRTConnect](https://ompl.kavrakilab.org/classompl_1_1geometric_1_1RRTConnect.html)

### 7.5 预算与可复现性

支持时间、最大扩展次数、最大节点数和最大几何查询次数预算。交互运行以时间预算为主；确定性回归优先采用固定操作预算。

相同随机种子并不自动保证跨编译器、标准库、线程调度和时间预算完全复现。报告应记录环境；必要时保存采样序列，以回放方式定位差异。

## 8. 路径优化与质量度量

### 8.1 基础指标

| 指标 | 定义 |
|---|---|
| 平移长度 | 相邻路径状态位置差的范数之和，单位米 |
| 累计旋转 | 相邻状态最短旋转角之和，单位弧度 |
| 路径节点数 | 路径中保存的位姿数量 |
| 最小采样间隙 | 在指定评估采样下测得的最小分离距离 |
| 首条路径耗时 | 开始规划至首条通过验证路径的耗时 |
| 总耗时 | 搜索、复核和优化分别记录，并给出总值 |
| 查询成本 | 状态检查、运动检查、窄相碰撞和距离查询次数 |

“最小采样间隙”不等于整条连续路径间隙的严格下界。没有完成距离评估时保存 `null` 或明确的未计算状态，不能填零。

### 8.2 Shortcut 简化

1. 保留原始路径。
2. 选择两个不相邻路径位置，生成直接插值连接。
3. 使用相同或更严格的运动验证器检查替换段。
4. 计算替换前后的平移、旋转和其他启用指标。
5. 按所选目标接受改进，否则保留旧段。
6. 达到尝试次数或时间预算后停止。
7. 对整个改进路径重新复核。

默认采用显式目标 `J = translation_length + rotation_weight * accumulated_rotation`，并同时保留两项原始指标。该目标只指导简化，不代表“整体质量”或全局最优。

若启用“不降低采样间隙”的优化约束，必须对两条路径使用同一评估策略，并说明它仍是采样层面的比较。

不直接用普通三维样条平滑位置后宣称路径仍有效。任何改变位置、方向或插值曲线的操作都必须重新验证。

## 9. 三组演示场景

三组场景由参数化实体生成。以下尺寸只用于初始构造与调试，不视为已经验证可行的场景；正式场景参数在参考运动和约束检查完成后冻结。

### 9.1 场景 A：长条通过带障碍的通道

**问题：** 中心点能通过的位置，长条整体可能无法通过。

**场景构成：**

- 一个长条箱体，例如长宽高比例约为 `6:1:1`。
- 两侧墙体、地板和必要的顶部边界。
- 通道内部的柱体或箱体障碍，形成偏置通路。
- 起点和终点位于障碍两侧。

**可调参数：** 长条长度与厚度、通道宽度、障碍物位置、起终朝向。

**展示内容：**

- 显示参考点轨迹与完整刚体运动的区别。
- 高亮长条端部与障碍物的碰撞。
- 修改长条尺寸后重新规划。
- 对比原始路径和简化路径。

**验收：**

- 至少一个中心点直线通过而实体运动被拒绝的明确案例。
- 至少一个保存并验证过的可行参考运动。
- 不允许从通道物理边界外绕行。
- 修改尺寸后，旧路径和缓存查询立即失效。

### 9.2 场景 B：L 形物体通过走廊转角

**问题：** 需要协调平移与旋转，单独平移或固定方向运动不足以通过。

**场景构成：**

- 两个相交箱体组成的 L 形刚体，两个臂可具有不同长度。
- 直角走廊、内角障碍和限制绕行的外围墙体。
- 起终点分别位于转角两侧。

**可调参数：** 两个臂长、截面、走廊宽度、转角内侧障碍尺寸和高度空间。

**展示内容：**

- 通过姿态残影显示进入、转向和退出过程。
- 点击路径段检查两个端点与中间旋转状态。
- 显示最接近转角内壁的位置和距离连线。
- 展示搜索失败的扩展边及其碰撞对象。

**验收：**

- 场景中的有效解包含显著方向变化。
- 保存一个“两端有效，但中间旋转碰撞”的确定性回归案例。
- 组合刚体采用统一位姿，组成部分之间相对变换恒定。
- 参考运动经完整验证，规划器结果与参考运动分别保存。

### 9.3 场景 C：不对称物体通过错位开口

**问题：** 需要使用真正的三维朝向变化，不能退化为地面二维寻路。

**场景构成：**

- 三个或更多箱体组成的非对称刚体，具有明显偏置或突出部分。
- 两道具有错位开口的障碍墙，开口的高度或方向不同。
- 地板、天花板和外侧约束封闭旁路。
- 起终状态分别位于两道开口之外。

**可调参数：** 开口宽高、中心偏移、墙间距、突出部分尺寸和高度。

**展示内容：**

- 通过姿态残影与坐标轴展示俯仰、滚转和偏航的变化。
- 展示完整 SE(3) 搜索与受限运动搜索的实验比较。
- 调节开口尺寸，观察求解难度、间隙和查询成本的变化。

**验收：**

- 保存一个实际包含离开固定平面方向的可行参考运动。
- 验证外部绕行被物理边界阻止。
- 若声称某种固定朝向或平面约束下必定不可行，提供几何论证；受限规划器超时不构成证明。
- 展示的姿态来自求解与验证结果，不能用预置参考运动冒充规划器输出。

### 9.4 每组场景的固定资产

每组场景均保存：

- 参数化生成说明与冻结后的 JSON。
- 起终位姿、采样范围和物理边界。
- 一条已知可行并独立验证的参考运动；未获得之前标记“待验证”。
- 至少一个局部碰撞、接触或穿越障碍的确定性负例。
- 场景版本、内容哈希和用途说明。
- 用于性能实验的一组尺寸变体，与正确性固定场景分开管理。

“已知不可行场景”应限于可明确证明的构造，例如实体封闭隔断；不要把随机搜索失败的场景归入这一类别。

## 10. 交互界面设计

### 10.1 布局

- **中央三维视图**：模型、障碍、路径、姿态残影和调试叠加。
- **左侧场景面板**：场景选择、对象列表、尺寸、起终位姿和边界。
- **右侧规划面板**：算法参数、种子、预算、检查精度与启动/取消。
- **底部播放与统计区**：进度、单步、路径比较、状态、耗时和查询次数。

### 10.2 视图与拾取

- 支持轨道旋转、平移、缩放、重置和聚焦选中对象。
- 支持实体、线框和局部坐标轴显示。
- 鼠标拾取将屏幕位置转换为世界射线，返回最近命中对象。
- 拖动操作和数值输入共用位姿修改入口，统一触发结果失效。
- 法线使用正确的变换；深度测试与透明残影应避免误导遮挡关系。

### 10.3 结果表达

| 元素 | 表达方式 |
|---|---|
| 起点与终点 | 不同颜色和文字标签，显示朝向 |
| 原始与简化路径 | 独立颜色、图例和开关 |
| 关键姿态 | 半透明实体或线框残影 |
| 碰撞 | 高亮涉及的组成部分与障碍物 |
| 最近距离 | 最近点之间的连线、数值与单位 |
| 搜索树 | 抽样显示位置连线，选中节点时显示完整朝向 |
| 数值不确定 | 专用状态与原因，不使用“有效”颜色 |
| 过期结果 | 明确标为失效，要求重新计算 |

搜索树投影到三维位置后的连线不包含完整六维信息；不能用位置图解释所有状态差异。标签和图例不能只依赖颜色。

### 10.4 运行状态

```text
Idle -> ValidatingInput -> Planning -> ValidatingPath -> Ready
                                  -> BudgetExhausted
                                  -> Cancelled
                                  -> Error
Ready -> Optimizing -> ValidatingPath -> Ready
任何计算输入变化 -> 结果失效并取消相关旧任务
```

优化失败时保留原来已验证的路径。界面不得将旧任务迟到的结果覆盖到新场景。

## 11. 软件架构

### 11.1 模块依赖

```text
app / viewer                    cli / benchmark
      |                               |
```

### 11.3 接口职责

```text
GeometryQuery.check(scene, pose, query_options)
StateValidator.validate(scene, pose, validation_policy)
MotionValidator.validate(scene, from, to, validation_policy, stop_token)
Planner.solve(request, stop_token, progress_sink)
PathOptimizer.optimize(path, request, optimization_options, stop_token)
PathEvaluator.evaluate(path, scene, evaluation_policy)
SceneIO.read/write(...)
ResultIO.read/write(...)
```

以上为接口设计，不是已有 API。每个返回值都应区分失败、不确定、取消和正常结果，避免用单个布尔值吞掉诊断。

### 11.4 所有权与并发

- 使用 RAII 管理文件、线程和图形资源。
- 大型几何通过不可变共享对象复用；可变规划状态由单个任务拥有。
- 初版采用 UI/渲染线程加一个后台规划任务，先保证一致性，再考虑更细粒度并行。
- 可用 `std::jthread` 与停止令牌管理取消，但停止检查需落实到扩展、连接和采样验证循环。
- 后台任务使用启动时的 `SceneSnapshot`，不读取正在被 UI 修改的容器。
- 进度通过有容量限制的消息或快照传递，避免每次碰撞查询都刷新界面。
- 所有结果带 `scene_revision` 与 `request_id`；消费前核对。
- OpenGL 资源只在拥有对应上下文的线程创建、更新和释放。
- 取消必须清理临时任务状态，不能留下仍写入共享数据的线程。

读取时校验字段、类型、数值范围、对象编号唯一性和几何支持范围。未知版本应明确拒绝或走显式迁移，不能静默按旧格式解释。

### 12.2 路径文件

保存场景哈希、请求编号、位姿序列、四元数顺序、插值方法、起终容差、生成算法和完整验证配置。加载路径时核对场景；不匹配时只能作为参考显示，不自动获得有效状态。

### 12.3 运行报告

报告至少记录：

- 运行编号、时间、软件提交版本、依赖版本与构建配置。
- 操作系统、CPU、内存；涉及渲染性能时额外记录 GPU 和分辨率。
- 场景哈希、完整参数、随机种子和终止条件。
- 搜索结果与实际停止原因。
- 首解、复核、优化和总耗时。
- 节点数、扩展数和分层查询次数。
- 原始与简化路径指标。
- 验证模式、分辨率、检查样本数和不确定情况。

失败运行同样保存；缺失数据使用未计算状态。未经运行的指标不得在报告模板中填入看似真实的数值。

## 13. 测试与基准设计

### 13.1 数学与几何测试

| 类别 | 必须覆盖的情况 |
|---|---|
| 变换 | 单位、逆、组合顺序、局部/世界往返 |
| 四元数 | `q/-q` 等价、接近零旋转、接近 π、非法范数 |
| 距离 | 已知解析值、对称性、最近点位置、不同尺度 |
| 碰撞 | 分离、接触、部分重叠、完全包含、近乎平行 |
| 组合刚体 | 任一组成部分碰撞、整体最近距离、内部组成部分重叠 |
| 粗筛 | 全遍历与 BVH 一致，正余量下无错误排除 |
| 输入 | NaN、无穷、负尺寸、缺失字段、未知版本 |
| 拾取 | 命中、未命中、边界点、退化面、视图变化 |

增加性质测试：同时施加相同刚体变换后距离与相交关系保持一致；交换对象顺序后距离一致；改变四元数符号不改变几何结果。

### 13.2 运动与规划回归

- 起终点相同，返回零长度有效路径。
- 起点碰撞与终点碰撞分别报告。
- 端点均有效但中间穿过薄障碍。
- 原地旋转时物体突出部分扫过障碍。
- 两棵树交换后仍正确输出起点到终点路径。
- 接近但未连接的两棵树不得误报成功。
- 预算耗尽、取消、数值不确定和验证未完成各自保持正确状态。
- 优化不改变起终点，不降低验证要求。
- 场景编辑后，旧路径和旧后台结果不得成为当前结果。
- 序列化回读保留位姿、单位和验证元数据。

### 13.3 独立对照

自研几何查询先与解析案例比较，再与 FCL 在相同形状、单位、接触规则和容差下对照。发生分歧时保留最小复现案例；不能默认任何一方绝对正确。

自研 RRT-Connect 与 OMPL 对照时尽量共享场景、状态有效性与运动验证策略，记录状态距离和参数映射差异。若二者使用同一几何后端，规划结果一致并不能独立证明该后端正确。

### 13.4 基准矩阵

围绕三组场景，逐步比较：

| 变量 | 对比内容 |
|---|---|
| 几何加速 | 全遍历与 BVH |
| 运动精度 | 多档平移、旋转和表面运动步长 |
| 通道难度 | 开口宽度、错位程度、障碍密度 |
| 路径优化 | 原始路径与固定预算 shortcut |
| 规划实现 | 自研与 OMPL，在可对齐条件下比较 |

每次实验只改变待研究因素，其余条件固定。正式性能运行使用 Release 构建并关闭实时搜索树绘制；UI 性能单独测试。

初始实验可采用每组配置 30 个预先固定的种子。该数量是实验起点，不保证统计充分；报告成功率分母、区间估计和时间分布。重复运行与配置比较的组织方式可参考 OMPL 的 Benchmark 机制。[参考：OMPL Benchmark](https://ompl.kavrakilab.org/benchmark.html)

成功运行报告首解时间分布和路径质量；失败运行保留超时或其他终止原因，不能只对成功样本计算均值后把它当作整体表现。样本过少时不强调高分位指标。

### 13.5 性能验收原则

- 正确性回归必须全部通过。
- 受支持的已知可行场景需在固定回归种子和操作预算下得到经验证的路径；冻结验收配置，避免随实现临时改宽条件。
- 随机成功率用于报告算法表现，不能替代正确性测试。
- 帧率、取消延迟、内存和耗时目标在参考硬件确定后量化。
- 优化结果不得以牺牲验证分辨率或隐瞒失败样本换取性能提升。

## 14. 分阶段实施与验收

### P0：工程与数据约定

**交付：** 可构建工程骨架、最小场景、基础测试和依赖记录。

**验收：** 全新构建目录可以完成配置与编译；无界面测试可独立运行；非法输入返回可读错误。

**依赖：** P0。

**验收：** 模型变换与几何查询使用同一位姿；组合部分相对关系保持；数学与拾取案例通过。

**依赖：** P1。

**验收：** 解析案例与对照通过；能检测预设的中途穿墙和旋转扫碰；明确显示检查分辨率与未知状态。

**依赖：** P2。

### P4：路径简化与三组演示

## 15. 项目风险与处理

| 风险 | 处理方式 |
|---|---|
| 狭窄通道难以采到有效状态 | 保留已知可行参考运动，区分算法失败与场景无解 |
| 离散运动检查漏检 | 显示分辨率、增加薄障碍负例，进阶研究保守验证 |
| 模型与碰撞代理不一致 | 首版由同一解析参数生成；代理差异显式显示 |
| 数值误差导致接触抖动 | 统一尺度和容差策略，保守处理不确定区间 |
| 三组场景被外部绕行破解 | 物理边界建模，逐段检查参考运动和求解路径 |
| 库调用掩盖实现贡献 | 自研与复用分工明确，保留独立测试和对照 |
| GUI 计算耦合造成卡顿 | 后台计算、不可变快照、有界进度队列 |
| 旧结果覆盖新场景 | 场景版本、请求编号与取消机制 |
| 基准结论失真 | 固定配置、多种子、保留失败样本，关闭绘制再测计算性能 |
| 任意模型支持拖延核心闭环 | 首版限制解析形状与组合刚体 |
